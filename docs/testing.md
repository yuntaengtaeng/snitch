# snitch 직접 시험하기

자동 테스트(`claude plugin test .`)는 순수 로직만 확인합니다. 패널, 도구 호출, 서브에이전트처럼 Claude Code 안에서만 보이는 동작은 이 문서의 순서대로 직접 확인합니다.

## 준비

Git Bash에서 저장소 폴더로 이동한 뒤 실행합니다.

```
scripts/try.sh
```

- `~/snitch-test`에 README 하나만 있는 깨끗한 git 저장소를 새로 만들고, 그 안에서 이 저장소의 snitch를 띄웁니다.
- 실행할 때마다 시험 저장소를 지우고 다시 만듭니다. 이 스크립트가 만든 폴더(`.git/snitch-test` 표시가 있는 폴더)만 지웁니다.
- 다른 경로를 쓰려면 `scripts/try.sh /c/Users/me/other-test`처럼 인자로 넘깁니다.

설치된 snitch가 함께 켜져 있으면 상태줄이나 패널이 두 번 나올 수 있습니다. 그럴 때는 `/plugin`에서 설치된 snitch를 잠시 꺼 주세요.

## 시나리오

각 단계의 프롬프트를 그대로 입력하고 **확인**을 봅니다.

### 1. 시작

입력창에 아무 글자나 쓰기 시작합니다.

- [ ] 우측에 `snitch` 패널이 열림 (안 열리면 `/snitch`)
- [ ] 서브에이전트가 없어서 에이전트 구역이 보이지 않음
- [ ] `변경 파일 0`, `없음`

### 2. 작성자 메모

```
README에 이 저장소가 snitch 시험용이라는 설명을 한 줄 추가해줘
```

- [ ] 대화에 `change_note` 도구 호출이 보임
- [ ] 패널의 `README.md` 아래에 Claude가 남긴 이유가 바로 나옴 (`변경 이유 정리 중…` 없이)
- [ ] 제목 줄에 5h, 7d 남은 한도 막대가 나옴 (구독 요금제만)
- [ ] 하단 상태줄이 `모델 effort  |  남은 한도 5h N%, 7d N%` 형식

### 3. Bash로 만든 파일

```
Bash의 printf로 notes/todo.md 파일을 만들어서 할 일 세 개를 적어줘
```

- [ ] `A todo.md`가 변경 파일에 나옴
- [ ] 아래에 이유와 `notes` 폴더가 나옴

### 4. 서브에이전트

```
general-purpose 서브에이전트 두 개를 백그라운드로 동시에 띄워서,
하나는 notes/a.md에 할 일 목록을, 다른 하나는 notes/b.md에 회의 메모 예시를 만들게 해줘
```

- [ ] 에이전트 구역이 나타나고 서브에이전트가 작업 이름으로 보임
- [ ] 작업 중에는 `●`와 경과 시간, 아래에 마지막 툴 호출 (경로는 파일 이름만)
- [ ] 끝나면 `✓`와 걸린 시간
- [ ] `a.md`, `b.md` 아래에 이유와 `notes, 작업 이름`이 나옴

### 5. 새 요청 때 정리

```
파일은 고치지 말고 지금까지 한 일을 한 줄로 요약해줘
```

- [ ] 끝났던 서브에이전트가 목록에서 빠지고, 에이전트 구역이 다시 숨겨짐

### 6. 명령

```
/snitch text
/snitch why
/snitch
```

- [ ] `/snitch text`: 패널과 같은 내용이 텍스트로 나옴
- [ ] `/snitch why`: `변경 파일 N개의 이유 다시 정리 중` 뒤에 이유가 다시 채워짐
- [ ] `/snitch`: 패널이 닫힘, 한 번 더 입력하면 다시 열림
- [ ] `/changes`도 같은 동작

### 7. 커밋

```
바뀐 파일 모두 커밋해줘
```

- [ ] 커밋 구역에 커밋이 생기고 `변경 파일 0`이 됨

### 8. 요청별 변경 이력과 파일 상세

```
README에 설치 방법 섹션을 추가해줘
```

다음 요청으로 같은 파일을 한 번 더 고칩니다.

```
README 설치 방법 아래에 주의 사항 한 줄을 추가해줘
```

- [ ] 패널의 `README.md` 아래에 두 번째 이유와 `이력 2`가 나옴
- [ ] `/snitch why README.md`: 두 이유가 요청 순서대로 요청 문구와 함께 나옴
- [ ] 패널의 `README.md` 행을 누르면 상세 화면, `변경 이유 2`와 hunk별 diff가 보임
- [ ] hunk의 `수정 요청`을 누르면 입력칸이 열리고 바로 입력할 수 있음
- [ ] `이 부분은 원래대로 되돌려줘`를 입력하고 Enter: 대화에 `[README.md N-M줄] ...` 요청이 보이고 Claude가 그 부분만 고침
- [ ] 응답이 끝나면 상세 화면의 diff와 이력이 새로 바뀜
- [ ] Esc 또는 `‹ 목록`으로 목록 복귀, 목록에서 Esc는 패널 닫기
- [ ] 상태줄과 패널 제목 줄의 5h 한도 뒤에 초기화 시각(예: `15:40`)이 나옴

### 9. 직접 커밋

```
README에 한 줄 소개를 추가해줘
```

1. 다른 터미널에서 시험 저장소로 가서 직접 커밋합니다: `git commit -am "직접 커밋"`
2. 아무 요청이나 하나 보냅니다 (예: `파일은 고치지 말고 안녕이라고만 답해줘`).
   - [ ] `README.md`가 변경 파일에서 빠짐, `/snitch why README.md`는 찾지 못함으로 나옴
   - [ ] 요청을 보내는 동안 변경 파일 개수가 줄었다 늘었다 하지 않음

### 10. 기억할 거리 보드

```
snitch 보드로 관리해줘. 라이선스를 MIT와 Apache-2.0 중에 고르는 결정을 선택지와 함께 남기고, 할 일로 README 작성, .gitignore 작성, CI 이슈 등록을 추가해. README와 .gitignore만 지금 하고 나머지는 남겨둬
```

- [ ] 대화에 `snitch 보드: 할 일 +3, 결정 +1` 같은 흐린 한 줄만 보임
- [ ] 패널 맨 위에 테두리 카드로 `결정 필요 1`, 그 아래 `[ MIT ]` `[ Apache-2.0 ]` `[ 직접 답하기 ]`
- [ ] 작업하는 동안 할 일에 `▸ ... 진행 중`, 끝난 것은 `✓ N개 완료`로 접힘, 막대가 채워짐
- [ ] `[ MIT ]`를 누르면 `[결정 d1] ...: MIT`가 내 요청으로 들어가고, 응답 뒤 결정 카드가 사라짐
- [ ] `/clear` 뒤 보드가 비고 구역이 숨겨짐

```
이 저장소 상태를 짧게 설명하고, 다음에 무엇을 할지 나에게 질문으로 물어봐
```

- [ ] Claude가 질문으로 끝내면 결정 카드가 생김 (snitch가 한 번 돌려보낸 경우 포함)

링크는 GitHub 원격이 있는 저장소에서 `이 브랜치를 push하고 PR을 만들어줘`로 확인합니다.

- [ ] `링크` 구역에 `저장소이름 PR #N`이 나오고 누르면 열림

## Haiku 대비책 시험

Claude가 메모를 남기지 않았을 때 Haiku 요약이 채우는지 보려면 `hooks/config.ts`에서 `ENABLE.changeNotes`를 `false`로 바꾸고 2번 시나리오를 다시 합니다. 이유 줄이 `변경 이유 정리 중…`을 거쳐 채워지면 정상입니다. 같은 파일을 두 번째 요청으로 고쳤을 때 두 번째 이유가 첫 변경이 아닌 새 변경만 설명하는지도 봅니다. 확인한 뒤에는 `true`로 되돌립니다.

## 문제가 있을 때

`scripts/try.sh` 대신 시험 저장소에서 `claude --plugin-dir <이 저장소> --debug`로 실행하면, 훅이 실패한 이유가 디버그 로그에 `snitch:`로 남습니다.
